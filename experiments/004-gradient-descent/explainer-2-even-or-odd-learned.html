Even or odd, learned

Part 1 built the mental model: a neuron is a weighted vote, it can only make one straight cut, the right inputs make odd and even one cut apart, and a loop that fixes its mistakes finds the weights.

This part builds that neuron for real, in about a hundred lines of Python, and upgrades the learning rule into the one modern networks use. We'll go quickly through the parts you've seen and slowly through the parts that are new.

Chapter 1

The machine, in one paragraph

A neuron is a list of 40 weights and one bias. To feed it a number like 1010, we expand the number into 40 switches: each of the four digit places gets ten switches, one per possible digit, and the one that matches is on. The neuron multiplies each switch by its weight and adds everything up, bias included. Out comes one number, the score: positive means “odd”, negative means “even”.

That's all of it. Type a number and watch both lists.

40 switches in, one score out
the switches · the input · changes with every number
the weights · the memory · ringed: the four that count
Both grids are 4 × 10. Are they the same kind of thing?

No, and mixing them up is the most common confusion here. The switches are the input. They change with every number, and they're only ever 0 or 1, exactly four ones. The weights are the memory, what training left behind. They're fixed once training ends, and they can be any number, negative included. Because an off switch multiplies its weight by 0, only the four ringed weights ever matter for a given number.

Note too what “the weight for digit 1 is 4” means. The 4 is a label: it picks which weight to use. It isn't added. With fresh weights every weight is 0, so the score is 0 whatever the number.

in the code · switches.py and neuron.py
def switches_for(number):
    """A number -> its row of 40 switches, as a list of 0s and 1s."""
    switches = [0] * SWITCH_COUNT
    for place, digit in enumerate(f'{number:04d}'):
        switches[switch_for(place, int(digit))] = 1      # "digit 4 is 7" is switch 37
    return switches

class Neuron:
    def __init__(self):
        self.weights = [0.0] * SWITCH_COUNT   # one weight per switch, all start at 0
        self.bias = 0.0

    def score(self, switches):
        total = self.bias
        for weight, switch in zip(self.weights, switches):
            total += weight * switch
        return total

The right answers come from an oracle: oracle.py is literally return number % 2. That isn't cheating. It's the answer key at the back of the book, and the neuron never sees its code. In real projects the oracle is people who labelled the data. In 002, it was a perfect tic-tac-toe player.

Chapter 2

From “wrong” to “how wrong”

Part 1's learning rule only woke up on mistakes, and then it moved every weight that was on by a full ±1. That has two weaknesses:

  • It can't tell barely wrong from badly wrong. Both get the same ±1.
  • Once it's right, it learns nothing, even if it was only right by a hair. A score of +0.001 counts as a confident “odd”.

Better: learn from every example, by an amount that depends on how far off it was. The answer is 1 for odd and 0 for even, so the simplest measure is the difference. Call it the miss:

miss = score − answer

Then push the score the opposite way to the miss. Try that below.

Set the answer to odd, the comparison to raw, and drag the score to +3. Was the neuron right? Which way does the push go?
the miss: raw score vs squashed

With the raw score, a neuron that is sure and right (+3 for an odd number) gets a miss of +2 and is pushed back towards “even”. It's punished for being right, and the surer it is, the harder the punishment. In chapter 4 you can turn this off in the real trainer and watch the weights run off to infinity.

The fix is to squeeze the score into the range 0 to 1 before comparing it with the answer. Very positive becomes nearly 1, very negative becomes nearly 0, and 0 becomes 0.5, “no idea”. Switch to squashed and drag again: a score of +3 becomes 0.95, the miss is a tiny −0.05, and the push is gentle and in the right direction.

That S-shaped squeeze is the sigmoid. Its output is the neuron's confidence that the number is odd. Over 0.5 means it guesses odd, which is exactly “score above 0”, so the cut is in the same place as before. Only the learning changes.

in the code · neuron.py and the loop in train.py
def squash(score):
    """Squeeze any score, however big or small, into 0..1. Proper name: the sigmoid."""
    return 1 / (1 + math.exp(-score))

confidence = neuron.confidence(switches)     # squash(score)
miss = confidence - answer                   # > 0: said "odd" too strongly
Compare the confidence, not the raw score, with the answer. Then being sure and right costs almost nothing, and being sure and wrong costs a lot.
Chapter 3

The nudge

Part 1's rule, side by side with the new one:

part 1: fix mistakespart 2: nudge
whenonly on a mistakeon every example
which weightsthe ones whose switch was onthe ones whose switch was on
by how much±1−learning rate × miss

Same idea, made smooth. The learning rate (0.1 here) is how big “a little” is. Step through it. The first two numbers are fixed so we can talk about them; after that they're random.

one nudge at a time
You've seen this in part 1: the weight for “digit 2 is 8” goes up on 4817. On 6890, does it come back down by the same amount?This time the size of the push depends on the miss.

Almost: up 0.050, down 0.052. Over thousands of examples, the same tally logic from part 1 plays out with fractions instead of whole votes. Weights linked to the answer drift one way, and the others cancel out. Because the miss shrinks as the neuron gets surer, the pushes shrink too, so it settles instead of stopping dead. This is gradient descent: feel which way is downhill for the miss, and take a small step that way.

in the code · nudge.py
def nudge(neuron, switches, miss, learning_rate):
    for switch_number, switch in enumerate(switches):
        # An off switch (0) had no hand in this answer, so its weight moves by 0.
        neuron.weights[switch_number] -= learning_rate * miss * switch
    neuron.bias -= learning_rate * miss          # the bias is in every answer
Chapter 4

Two thousand nudges later

Now let it run for real: 2,000 training numbers, a nudge on each, five passes through the pile. Each pass is called an epoch.

If it gets all 2,000 right, how do we know it learned the rule and didn't memorise 2,000 answers?

We keep 1,000 other numbers aside and never nudge on them. That's the test set, the hidden tests from part 1's TDD analogy. If it's right on those, it found the rule.

in the code · train.py
train = examples[:2000]   # to learn from
test = examples[2000:]    # never learned from; checks it found the rule, not the answers

for round_number in range(1, ROUNDS + 1):
    rng.shuffle(train)
    for switches, answer in train:
        # The three steps of learning, on one example: guess, see how wrong, move the weights.
        confidence = neuron.confidence(switches)
        miss = confidence - answer
        nudge(neuron, switches, miss, LEARNING_RATE)
    report(f'round {round_number}')

Chapter 6

Its XOR: divisible by 3

It's tempting to see the four rows as four neurons, one per digit. But it's one: all forty switches feed into one sum, and there's one answer.

what we built: 40 switches, one neuron

Go back to the trainer, switch the rule to divisible by 3?, and press Play.

Predict first: will it get to 100% again?

It won't. Only a third of numbers are divisible by 3, so saying “no” to everything already scores about 67%. Training then makes it slightly worse, settling in the mid-60s.

This is part 1's “exactly one” problem again. Divisibility by 3 depends on all the digits together (on their sum). A 5 in first place is good news if the rest add up to 1 and bad news if they add up to 2. A sum of fixed weights can't say “this digit matters, depending on the others”. There's no single straight cut.

The fix is a row of neurons in the middle. Each one looks at all the switches and learns its own combination, and one more neuron reads their answers. That middle row is a hidden layer, and training it needs the blame to pass back through each neuron. That's backpropagation, and it's why the smooth sigmoid matters: blame can flow back along a curve, but not over a cliff.

next experiment: a hidden layer

Why must each hidden neuron see every digit? If each one only saw its own digit, the final neuron would still just be adding up one opinion per digit, which is what we already have.

try it in the code · oracle.py
def oracle(number):
    return 1 if number % 3 == 0 else 0     # gets stuck around 64%
