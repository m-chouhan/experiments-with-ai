Even or odd, learned

4817

Is it odd? You knew instantly. You looked at the last digit, saw a 7, done. You could write that rule as one line of code, n % 2.

Now suppose you're not allowed to write that line. All you get is a pile of numbers, each one labelled odd or even, and one artificial brain cell. Can it find the rule by itself?

It can. To see how, we start with a real brain cell.

Chapter 0

A brain cell, in one picture

A neuron in your brain listens to other neurons. Each one sends it a signal, and each connection has a strength. Some connections are strong, some are weak, and some hold the cell back instead of egging it on.

The neuron adds up everything coming in. If the total crosses a threshold, it fires. If not, it stays quiet. All or nothing.

Here's a made-up one that decides whether you go for a run. Play with it.

one neuron: should I go for a run?
With “sunny” and “tired” both on, what's the smallest change that gets you out the door? There's more than one answer: a signal, a strength, or the threshold.

In 1943, Warren McCulloch and Walter Pitts wrote exactly this down as maths: signals of 0 or 1, multiply each by its strength, add them up, fire if the total is over the threshold. In 1958, Frank Rosenblatt asked the question this whole page is about:

Who sets the strengths? You just did, by hand. Rosenblatt's “perceptron” set them from examples.

One last bit of tidying. “Fire if total ≥ threshold” is the same as “fire if total − threshold ≥ 0”. So instead of a threshold we keep one extra number, called the bias, and add it to the total. Then the rule is just: is the total positive?

From here on, a strength is called a weight — which is just the everyday word. A weight says how much one fact counts, and which way it votes. Big and positive pulls towards odd, big and negative pulls towards even, and zero means the neuron ignores that fact entirely. You set these by hand a moment ago. From here on, the data sets them.

in the code · neuron.py
class Neuron:
    def __init__(self):
        self.weights = [0.0] * SWITCH_COUNT   # one weight per switch
        self.bias = 0.0                       # the threshold, flipped
Chapter 1

The question, and the answer key

Our neuron's job: look at a number from 0000 to 9999 and say odd or even.

To learn, it needs examples with the right answers. We get those for free from an oracle: something we already trust. Here, that's one line.

Isn't it cheating to use n % 2 to teach a machine n % 2?

No. The oracle is the answer key at the back of the textbook. The neuron never sees its code. It only ever sees question, answer, question, answer. In real projects the oracle is usually people who labelled the data (“this photo is a cat”). In 002, it was a perfect tic-tac-toe player.

in the code · oracle.py
def oracle(number):
    """1 if the number is odd, 0 if it's even."""
    return number % 2
Chapter 2

What should the neuron see?

The run neuron had three inputs. What should this one's inputs be? The obvious answer: one input, and it's the number.

Try it. Here's a neuron with one input (the number) and one weight, plus a bias. Can you set them so it gets odd and even right?Watch the accuracy. Try to beat 55%.
one input: the number itself
–right, on all 10,000

You can't. Look at the chart: whatever you do, the curve only ever goes one way. It can say “big numbers are odd” or “small numbers are odd”, but odd and even zig-zag: 4816 even, 4817 odd, 4818 even. A line that only goes one way can't zig-zag. The best it can do is a coin flip.

Size is the wrong thing to show it. So let's show it something it can attach a weight to. Each of the four digit places gets a row of ten switches, one for each possible digit, and we turn on the one that matches. Four rows of ten: forty switches.

40 switches

Now “the last digit is 7” is its own switch, with its own weight. And “the last digit is 8” is a different switch, so it can have the opposite opinion. Always exactly one switch per row is on. The name for this is one-hot encoding.

An aside: written in binary, odd/even is just the last bit, and a neuron gets it 100% right instantly. How you show the data decides how hard the problem is. GPT faces the same choice with words, and it uses switches too: one per token.

in the code · switches.py
def switches_for(number):
    """A number -> its row of 40 switches, as a list of 0s and 1s."""
    switches = [0] * SWITCH_COUNT
    for place, digit in enumerate(f'{number:04d}'):
        switches[switch_for(place, int(digit))] = 1
    return switches

# switch_for(3, 7) == 37, the switch meaning "digit 4 is 7"
# switches_for(4817)[37] == 1   and   switches_for(4818)[37] == 0
Chapter 3

Weights, and a score

Just like the run neuron: every switch gets a weight, plus one bias. That's 41 numbers, and they all start at zero. The neuron multiplies each switch by its weight and adds it all up. An off switch is 0, so it adds nothing. Only the four switches that are on count:

score = bias + weight for “digit 1 is 4” + weight for “digit 2 is 8” + weight for “digit 3 is 1” + weight for “digit 4 is 7”

Quick check: for 4817, is the score 4 + bias? Try it below before reading on.
the score, with real weights

No: the 4 in “1st digit is 4” is a label. It says which weight to use, not what to add. A fresh neuron's weights are all 0, so its score is 0. The trained weights add up to about +4.5, and nearly all of that comes from one weight: “4th digit is 7”.

Which leaves us with a problem. The oracle answers 0 or 1. The score can be +4.54, or −9, or anything. How do we compare them?

in the code · neuron.py
def score(self, switches):
    total = self.bias
    for weight, switch in zip(self.weights, switches):
        total += weight * switch   # off switch: weight x 0 = nothing
    return total
Chapter 4

How wrong was it?

The simplest idea: compare the score with the answer directly. Call the difference the miss:

miss = score − answer

Its sign says which way the neuron was off: positive means it said “odd” too strongly, negative means not strongly enough. To learn, we'll push the score the opposite way to the miss. Try it.

Set the answer to odd, the mode to raw, and drag the score to +3. Was the neuron right? Which way does the push go?
the miss: raw score vs squashed

With the raw score, a neuron that's sure and right (score +3 for an odd number) gets a miss of +2 and is pushed back towards “even”. It's punished for being right. The surer it gets, the harder it's punished. In the training scene below you can turn the squash off and watch the weights run away to infinity.

The fix is to squeeze the score into the range 0 to 1 before comparing it with the answer. Very positive becomes nearly 1, very negative becomes nearly 0, and 0 becomes 0.5, “no idea”. Switch to squashed above and drag again: now a score of +3 becomes 0.95, the miss is a tiny −0.05, and the push is a little nudge in the right direction.

That S-shaped squeeze is called the sigmoid, and its output is the neuron's confidence that the number is odd. Over 0.5, the guess is odd.

Rosenblatt's perceptron used a hard step instead (fire or don't), and on this task that works too. The smooth version earns its place in two ways. It says how wrong, not just wrong. And once neurons are stacked in layers, the blame has to flow back through each one, which needs a curve, not a cliff.

in the code · neuron.py and grade.py
def squash(score):
    """Squeeze any score, however big or small, into 0..1. Proper name: the sigmoid."""
    return 1 / (1 + math.exp(-score))

def miss_of(neuron, switches, answer):
    return neuron.confidence(switches) - answer      # confidence = squash(score)
Chapter 5

The nudge

Now the heart of it. After each example, move every weight that took part a little in the direction that would have made the miss smaller:

each weight that was on −= learning rate × miss

Switches that were off didn't touch this answer, so their weights stay put. The bias is always on, so it always moves. The learning rate (0.1 here) is how big “a little” is.

Step through it. The first two numbers are fixed so we can talk about them; after that they're random.

one nudge at a time
Before you press twice: the weight for “2nd digit is 8” goes up on 4817. What happens to it on 6890?6890 also has an 8 in second place, and it's even.

It comes right back down. It took part in an odd number and then in an even one, so the two nudges roughly cancel out.

Now scale that up. Over thousands of examples, “2nd digit is 8” shows up in odd and even numbers about equally, so it keeps getting pushed up and down and goes nowhere. But “4th digit is 7” only ever shows up in odd numbers. Every time it appears, it gets pushed the same way.

The weights that matter grow. The ones that don't cancel themselves out. Nobody tells the neuron which digit matters; the data does. That's gradient descent: feel which way is downhill for the miss, take a small step that way.

in the code · nudge.py
confidence = neuron.confidence(switches)   # in train.py: guess,
miss = confidence - answer                 # see how wrong,
nudge(neuron, switches, miss, LEARNING_RATE)   # move the weights

def nudge(neuron, switches, miss, learning_rate):   # in nudge.py
    for switch_number, switch in enumerate(switches):
        neuron.weights[switch_number] -= learning_rate * miss * switch   # off switch: moves by 0
    neuron.bias -= learning_rate * miss
Chapter 6

Two thousand nudges later

Now let it run for real: 2,000 training numbers, a nudge on each, five passes through the pile. Each pass is called an epoch.

If it gets all 2,000 right, how do we know it learned the rule and didn't just memorise 2,000 answers?

We keep 1,000 other numbers aside and never nudge on them. That's the test set. If it's right on those, it found the rule. It's the same reason an exam doesn't reuse the homework questions.

  • It reaches 100% on the test numbers within the first epoch, on numbers it never trained on.
  • The top three rows stay dim. The bottom row turns into stripes.

Chapter 7

Reading the neuron's mind

Here are the final weights from running python3 train.py in the repo. Type a number to see which four it uses.

final weights, from train.py
This grid has the same 4 × 10 shape as the switches in chapter 2. Is it the same thing?

No, and it's easy to mix them up. The switches are the input: they change with every number, and they're only ever 0 or 1. The weights are the memory: what training left behind. They're fixed now, and they can be any number, including negative ones. They aren't probabilities either. A probability only appears at the very end, after the squash.

Rows 1 to 3 sit near zero, so the first three digits are ignored. Row 4 alternates, about −4.6 for 0, 2, 4, 6, 8 and +4.6 for 1, 3, 5, 7, 9. Read it as a sentence: ignore everything except the last digit, and check whether that digit is odd. That's n % 2, written in weights. Nobody wrote it down.

Chapter 8

One neuron, or four?

It's tempting to see the four rows as four neurons, one per digit. But it's one: all forty switches feed into a single sum, and there's a single answer at the end. The rows are only how we lay the weights out for us to read.

what we built: 40 switches, one neuron

One neuron is enough for odd and even. Go back to the training scene, switch the rule to divisible by 3?, and press Play.

Predict first: will it get to 100% again?

It won't. Only a third of numbers are divisible by 3, so untrained, saying “no” to everything, it already scores about 67%. Training then makes it slightly worse, settling in the mid-60s.

Whether a number is divisible by 3 depends on all its digits together (on their sum). A 5 in first place is good news if the rest add up to 1, and bad news if they add up to 2. One sum of fixed weights can't say “this digit matters, depending on the others”.

So the four-neuron idea comes back, in a stronger form: a row of neurons that each look at all the switches, each free to learn its own combination, and one more neuron that reads their answers. That middle row is a hidden layer.

next experiment: a hidden layer

Why must each hidden neuron see every digit? If each one only saw its own digit, the final neuron would still just be adding up one opinion per digit, which is what we already have.

try it in the code · oracle.py
def oracle(number):
    return 1 if number % 3 == 0 else 0     # gets stuck around 64%

Is this a neural network? It's the smallest one: a single neuron. A neural network stacks many of them, so that the outputs of one layer become the switches for the next. Data, neuron, grade and nudge all stay the same. The network gets bigger, and the nudge has to pass blame back through the layers, which is called backpropagation.
