How a neuron learns

As a software engineer, you get a function by writing it:

the way you know
def is_odd(n):
    return n % 2

Machine learning gets the same function a different way. You write a function with blanks in it, and a loop fills the blanks in from examples. The loop doesn't know what odd means. Nobody tells it to look at the last digit. And yet it ends up looking at the last digit.

How? That's the only question on this page. Answering it takes five ideas, and you'll get to play with each one.

Idea 1

A neuron is a weighted vote

A brain cell listens to other cells. Each sends it a signal, and each connection has a strength: some strong, some weak, and some that hold the cell back. The cell adds up what comes in. If the total crosses a threshold, it fires. If not, it stays quiet.

Here's a made-up one that decides whether you go for a run.

one neuron: should I go for a run?
With “sunny” and “tired” both on, what's the smallest change that gets you out the door? A signal, a strength, or the threshold: any of them will do.

In 1943, Warren McCulloch and Walter Pitts wrote this down as maths. In code it's three lines:

a neuron
def neuron(inputs, weights, bias):
    total = bias + sum(w * x for w, x in zip(weights, inputs))
    return total > 0          # fire, or don't

Strength is called weight. The threshold is folded into one extra number, the bias: “fire if total ≥ 1” is the same as “fire if total − 1 ≥ 0”, so the bias is just −1. Now the rule is simply is the total positive?

Look at that function again. Where is the logic? Hint: it's not in the code.

The code is the same for every neuron that ever existed. What the neuron does lives entirely in the numbers you pass in. Change the weights and it's a different decision-maker. The weights are the program. So “learning” is going to mean: finding the numbers.

A neuron is a weighted vote. Each input votes with its weight, the bias is a head start, and the answer is the sign of the total.
Idea 2

A neuron draws one straight cut

Before asking how to find the weights, let's ask what any set of weights can do. Take the run neuron with just two inputs: sunny and friend coming, each 0 or 1. There are only four situations, the four corners of a square.

For every point in that square, the neuron's total is either positive (fire, shaded blue) or negative (stay in, shaded red). Drag the weights and watch the border move.

two inputs: what one neuron can separate
should runshould stay inshading = what the neuron says
Get 4 of 4 for “both”, then for “either”. Now try “exactly one”. Take your time with the last one.

“Exactly one” is impossible. The border between fire and don't-fire is always a straight line, because the total is a weighted sum, and a weighted sum changes evenly as you move across the square. “Exactly one” needs the two blue corners on one side and the two red corners on the other, and they sit diagonally. No straight cut separates them. This pattern is called XOR, and it famously stalled neural network research for over a decade.

Whatever the weights, a neuron splits its inputs with one straight cut. If the pattern isn't one cut away, no amount of learning will find it.
Idea 3

Odd and even, as a picture

Now our actual problem. The obvious design: one input, the number itself. Then the neuron's total is

score = weight × number + bias

That's y = mx + b, a straight line. Here's how to read the picture below, piece by piece:

  • Left to right are twenty numbers, 4810 to 4829.
  • The dots are the right answers. Odd numbers sit above the dashed middle line and even numbers sit below it, so the dots zig-zag.
  • The yellow line is the neuron's score for each number. The rule is the same as before: score above the middle means “odd”, below means “even”.
  • So the neuron gets a number right when its dot and the yellow line are on the same side of the middle. The shading shows which side the line is on.
Tilt and slide the line. How many of the twenty can you get?
one input, the number: a straight line vs a zig-zag

The most you can get is about eleven. A straight line crosses the middle once, so it can only ever say “everything after here is odd”. The answers cross the middle every single step. It's Idea 2 again: odd and even aren't one cut apart on the number line. Over all 10,000 numbers, the best any line can do is 50%, a coin flip.

The neuron isn't too dumb. It's looking at the problem from an angle where the answer can't be drawn with one cut.
Idea 4

Change what it sees, not how it thinks

So give it a better angle. Instead of one input, “the number”, give it ten inputs: “the last digit is 0”, “the last digit is 1”, …, “the last digit is 9”. Each is a switch, on or off. For any number, exactly one is on.

Each switch has its own weight. With just one switch on, the score is simply that switch's weight. 4817 gets the weight for “last digit is 7”, and 4818 gets the weight for “last digit is 8”: two separate numbers you can set however you like.

Here are the same twenty numbers. The ten sliders are the ten weights. Can you get twenty out of twenty?
ten inputs: one weight per last digit

Easy: push the odd digits up and the even digits down. Notice something about the score: it now zig-zags, even though the neuron is the same weighted vote as before. Nothing about the neuron got smarter. Its inputs got more expressive.

And look at the last line of the readout. Every number ending in 7 gets the same score, so if you got twenty out of twenty here, you got all ten thousand right. You set ten numbers by looking at twenty examples, and it works on numbers you never looked at.

In Idea 2's language, each switch is a new direction. In this ten-dimensional space, odd numbers and even numbers are one straight cut apart. The trick of turning a value into one switch per possibility is called one-hot encoding. GPT does the same thing with words: one switch per token in its vocabulary.

Choosing the inputs is choosing what's easy. With the right switches, a pattern that was impossible becomes one cut.
Idea 5

A loop that fixes its mistakes

You just set the weights by hand. You looked at the examples, saw which way each one was wrong, and moved the sliders. Could a loop that knows nothing do what you did?

In 1958, Frank Rosenblatt's answer was a rule so simple it feels like it shouldn't work. Show the neuron one example at a time:

  • Guess. Add up the weights of the switches that are on, plus the bias. Positive means “odd”.
  • Check against the right answer.
  • If it was right, do nothing.
  • If it said “even” for an odd number, add 1 to the weight of every switch that was on, and to the bias. If it said “odd” for an even one, subtract 1 from them.

That's it. Now let's make it harder: give it all four digits, forty switches, and don't tell it which digit matters. The rows are the four digit places, the columns are the ten digit values, and each cell is one weight. It starts with every weight at 0.

Before you press anything: the rule never mentions the last digit. Which weights do you expect to grow?

It goes straight back down. Now press “Run 100” a few times and watch the chart. The last row turns into stripes, and the other three rows just jitter around zero. After a few dozen mistakes it hardly makes any more, so it hardly changes any more. It has learned n % 2.

the whole learning rule (a sketch, not in the repo)
weights, bias = [0] * 40, 0
for number, answer in examples:
    switches = switches_for(number)                    # 40 zeros and ones
    score = bias + sum(w * s for w, s in zip(weights, switches))
    guess = 1 if score > 0 else 0
    if guess != answer:
        change = +1 if answer == 1 else -1             # which way it was wrong
        for i in range(40):
            weights[i] += change * switches[i]         # only switches that were on
        bias += change
Learning is a loop that turns every mistake into a tiny edit of the numbers.
The question

So why does that work?

Here's the part that matters most. Each step of the loop is mindless, so where did the understanding come from? Four reasons, and each one is visible in the scene above.

1. A weight is a tally of evidence. Read the rule again: a weight only changes when its switch was on during a mistake, by +1 on odd numbers and −1 on even ones. So after training, each weight is just a count: (mistakes on odd numbers this switch was part of) minus (mistakes on even numbers it was part of). It's a scoreboard for one piece of evidence.

2. Signal adds up, noise cancels. “Digit 2 is 8” turns up in odd and even numbers about equally, so its tally gets pushed both ways and goes nowhere. That's the grey line in the chart. “Digit 4 is 7” turns up only in odd numbers, so every push goes the same way, and it climbs: the yellow line. Nobody told the loop which digit matters. The only thing that survives thousands of pushes is whatever is consistently linked to the answer. That's what a pattern is. (It's the same reason averaging many noisy measurements gives you the true value.)

3. It stops when it's right. The rule only edits on mistakes. Once the pattern is in the weights, mistakes dry up and the numbers stop moving. It doesn't “know” it has finished; it just stops getting corrected.

4. It's too small to memorise. There are 10,000 numbers but only 41 weights. The neuron can't store “4817 is odd” and “4818 is even” separately. Anything it keeps has to be true of thousands of numbers at once. That squeeze is why it works on numbers it never saw. Learning is compression.

The same thing, in a software engineer's words

programming
you write:   the rules
you give:    an input
you get:     an answer
machine learning
you write:   a template + a fix-up rule
you give:    inputs AND answers
you get:     the rules (as numbers)

If that still feels like magic, think of test-driven development where the computer edits the code. The examples are the test suite. The weights are the code, written in a strange language of numbers. Each failing test causes a tiny automatic edit. You run the suite again and again until it passes. Then you check it against a few hidden tests it was never edited against, to make sure it learned the rule and didn't just special-case the visible ones.

You haven't stopped giving the machine instructions. You've moved up one level. Instead of “here's how to tell odd from even”, the instruction is “here's how to get less wrong”. That works whenever three things are true:

  1. The template can express the answer. Some setting of the weights solves it. Idea 3 failed this test; Idea 4 passed it.
  2. You can tell right from wrong. You have examples with answers. Here, n % 2 made them for free.
  3. Each mistake says which way to move. “Said even, should be odd” means push the on switches up.

Everything in deep learning, GPT included, is these three things at a much bigger scale.

Where this leaves us

What one neuron can't do, and part 2

Idea 2 already showed the limit: one neuron makes one straight cut, so “exactly one” (XOR) is out of reach. The fix is to feed neurons into other neurons, so that the first layer's outputs become the next one's inputs. Each layer gets to re-draw the picture so that the next one only needs one cut.

Part 2 builds this page's neuron for real, in about a hundred lines of Python. It upgrades the mistake rule into the smooth version every modern network uses: it learns from every example, by how wrong it was, not just whether it was wrong. Then it hits its own XOR: “is it divisible by 3?”
